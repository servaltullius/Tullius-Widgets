# 게임 안 자체 시험 모드 (2026-11-26)

브라우저 자동 테스트는 Chromium에서 돈다. 게임은 Prisma UI(Ultralight, 오래된 WebKit 계열)로 화면을 그리므로, CSS(`column-reverse`, `wrap-reverse`, `translateY(-100%)`)나 좌표 계산이 Chromium과 다르게 나올 수 있다. 지금은 이를 사용자가 게임에서 눈으로 확인한다. 자체 시험 모드는 같은 확인을 게임 엔진 안에서 숫자로 하고, 결과를 파일로 남겨 Claude가 읽고 판정하게 한다.

## 사용자 결정 (2026-11-26)
- 시험이 끝나도 그 게임 실행은 시험 전용 세션으로 둔다. 원래 설정으로 되돌려 계속하지 않는다. 그래서 설정 파일이 바뀔 길이 없다.
- 릴리스에도 넣는다. 표시 파일이 있을 때만 켜진다. 사용자도 버그 보고에 결과를 붙일 수 있다.
- 브라우저 테스트 시나리오 14개를 모두 게임 안에서 돌린다.

## 설계

### 켜는 방법
- 게임 폴더의 `Data/SKSE/Plugins/TulliusWidgets.selftest` 파일이 있을 때만 켜진다. MO2에서는 모드 폴더에 이 파일을 두면 된다. 내용은 보지 않는다.
- 플러그인은 게임이 시작될 때(kDataLoaded) 이 파일을 확인한다. 있으면 그 게임 실행 전체가 **시험 세션**이 된다.
- 세이브를 불러오거나 새 게임을 시작하면(kPostLoadGame/kNewGame), 화면이 뜨고 몇 초 뒤 시험을 한 번 시작한다.

### 시험 세션의 안전장치 (실제 설정을 건드리지 않음)
- 플러그인
  - 저장된 설정 파일을 화면에 보내지 않는다. 화면은 시험이 넣는 설정만 쓴다.
  - 화면이 보내는 설정 저장(`onSettingsChanged`)을 모두 버린다. 단축키 적용도 하지 않는다. 버릴 때마다가 아니라 세션에 한 번 로그에 남긴다.
  - 실제 게임 수치(`updateStats`)를 보내지 않는다. 시험이 넣는 가짜 효과·수치가 덮이지 않게 한다.
- 화면
  - 시험이 도는 동안 `onSettingsChanged`를 가로채 플러그인으로 보내지 않는다(이중 장치). 가로챈 저장은 "드래그하면 아래쪽 끝 좌표로 저장" 같은 확인에 쓴다.
  - 화면 아래쪽에 "자체 시험 모드: 설정이 저장되지 않습니다" 띠와 진행(n/전체), 끝나면 결과(통과/실패 수)를 보여 준다.
- 시험이 끝나도 그 게임 실행 동안은 시험 세션이 이어진다. 평소대로 쓰려면 표시 파일을 지우고 게임을 다시 시작한다. 띠에 이 안내를 적는다.

### 시험 실행기 (화면)
- `view/src/selftest/`에 둔다. 화면 묶음에 들어가지만, 플러그인이 `runSelfTest()`를 부를 때만 돈다.
- 시나리오는 브라우저 테스트(`view/e2e/`)와 같은 내용을 DOM으로 직접 한다.
  - 설정·수치 넣기: 브리지 함수(`updateSettings`, `updateStats`)를 그대로 부른다.
  - 클릭·드래그·크기 조절·키 입력: 마우스·키보드 이벤트를 만들어 보낸다.
  - 잴 것: `getBoundingClientRect`
  - 시나리오 사이에는 설정 창을 닫고 새 설정을 넣어 상태를 초기화한다. 페이지를 다시 불러오지 않는다.
- 판정은 화면 크기에 기대지 않는 관계로 한다(겹침, 제자리, 맞춤, 순서). 게임 화면은 4K일 수 있다.

### 결과
- 실행기가 결과 JSON을 `onSelfTestReport`로 플러그인에 보낸다(시작할 때, 시나리오마다, 끝날 때).
- 플러그인은 SKSE 로그 폴더(`Documents/My Games/Skyrim Special Edition/SKSE/`)의 `TulliusWidgets-selftest.json`에 쓰고, 요약 한 줄을 `TulliusWidgets.log`에 남긴다.
- 내용
  - 시나리오별 이름, 통과 여부, 실패 이유, 잰 값
  - 화면 크기, 기기 배율, 엔진 정보(User-Agent)
  - 시작·끝 시각
- Claude는 WSL에서 이 파일을 읽어 판정한다.

### 같은 실행기를 브라우저에서도 시험
- Playwright e2e에 "자체 시험이 Chromium에서 모두 통과" 시나리오를 둔다. 실행기 자체의 오류를 게임 전에 잡는다.

## 설계 검토 반영 (2026-11-26)
Codex는 사용 한도에 걸렸고, Neon 워커는 WSL에서 돌지 않았다. 그래서 새 맥락 Claude 검토자(읽기 전용)에게 맡겼다. 지적을 코드로 확인하고 아래처럼 설계를 바꿨다.

### 안전
- 플러그인이 파일을 쓰는 곳은 설정 저장과 프리셋 내보내기 두 군데다. 시험 세션이면 `NativeStorage`의 쓰기 함수들 자체가 거부한다(`SaveSettingsAsync`, `SaveSettings`, `ExportPreset`). 가져오기 요청도 무시한다.
  - 리스너에서도 먼저 거른다. 저장 요청에는 응답하지 않는다. `false`로 답하면 화면이 재시도하고 실패 띠를 띄운다.
- 시험 세션 판단은 플러그인 로드(`SKSEPlugin_Load`) 때 한다. 화면을 만들기(kDataLoaded) 전이라, 실제 설정 파일이 화면에 먼저 가는 일이 없다.
  - 확인 중 오류가 나면 일반 모드로 둔다. 로그에 경고를 남긴다.
- 시험 세션에서는 플러그인 단축키(설정 창, 위젯 숨기기, Esc 전달)를 무시한다. 시험 중 키 입력이 실행을 흐트러뜨리지 않게 한다.
- 화면에서 플러그인으로 가는 호출 8곳을 한 함수(`callNative`)로 모은다. 시험이 도는 동안에는 이 함수가 호출을 플러그인으로 보내지 않고 기록한다. `window.onSettingsChanged`를 덮어쓰는 방식은 쓰지 않는다. 게임에서는 Prisma가 이 함수를 연결하므로 덮어쓸 수 없을 수 있다.
  - 대상: 설정 저장, 읽기 실패 보고, 포커스 해제, 설정 창 열림, 내보내기, 가져오기, 단축키 입력 중, Esc 소유
  - 그래서 설정 창을 열어도 플러그인은 창이 열린 줄 모른다. 포커스를 잡아 게임을 멈추는 일도 없다.
- 띠는 시험이 끝날 때가 아니라 세션 내내 보인다. 표시 파일을 지우는 것을 잊은 경우의 유일한 안내이기 때문이다.

### 실행
- 시작: 플러그인 heartbeat가 다음을 모두 만족할 때 `runSelfTest("<실행 ID>")`를 부른다. 고정된 "몇 초 뒤"가 아니다.
  - 게임을 불러온 지 3초가 지남
  - 화면이 보이고, 화면을 숨기는 메뉴 상태가 아님
- 화면은 시작하자마자 "시작함"을 보고한다. 10초 안에 오지 않으면 3번까지 다시 부르고, 그래도 안 오면 결과 파일에 "시작 안 됨"을 남긴다. `Invoke`는 JS 함수가 없어도 성공을 돌려주기 때문이다.
- 결과는 시나리오가 끝날 때마다 보낸다(상태: 진행 중 n/전체 → 끝남). 세이브 다시 불러오기 등으로 중간에 끊겨도 어디까지 했는지 남는다.
- 세션이 시작될 때 예전 결과 파일을 지운다. 결과에는 다음을 넣는다.
  - 실행 ID
  - DLL 버전, 화면 빌드 정보
  - 화면 크기, 배율, User-Agent
- 시나리오마다 `App`을 다시 마운트한다(React `key` 변경). 앞 시나리오의 상태(읽은 파일 기록, 수치, 선택, 되돌리기 기록, 알림)가 남지 않게 한다.
  - 시험 설정에는 `rev`를 넣지 않는다.
  - 설정 창의 기억(분류, 위치, localStorage)은 시험 전 값을 되돌린다.
- 게임에서는 수치가 한 번 오기 전에는 위젯을 그리지 않는다(`hasLiveStats`). 그래서 시나리오마다 설정 다음에 수치를 먼저 보낸다.
- 모든 대기에 시간 제한을 둔다. 대기는 rAF가 아니라 타이머로 한다(숨겨진 화면에서 rAF가 멈출 수 있음). 시간이 넘으면 "시간 초과"로 실패 처리하고 다음 시나리오로 간다.
- 마우스 이벤트는 `elementFromPoint`로 그 자리에 의도한 요소가 있는지 먼저 확인한다(가려진 요소를 누르는 거짓 통과 방지).
  - 한계: 합성 이벤트는 Prisma의 실제 입력 변환(좌표, 배율, 키 값)과 플러그인의 Esc 경로를 거치지 않는다. 이것은 게임에서 손으로 확인한다.
- 화면 크기가 1080p가 아닐 수 있으므로, 크기 조절 폭은 목록 너비의 비율로 정한다.

### 결과 파일
- 경로는 SKSE 로그 폴더 API(`SKSE::log::log_directory()`)로 얻는다. GOG판처럼 폴더 이름이 달라도 된다.
- 임시 파일에 쓴 뒤 이름을 바꾼다. 경로는 UTF-8과 wide 문자열로 다룬다(사용자 이름이 한글일 수 있음).
- 크기 제한(1MB)을 넘으면 거부하지 않고, 요약과 "잘림" 표시만 담은 작은 파일을 쓴다.

### 검증 보강
- 시험 세션 판단과 결과 파일 쓰기는 표준 라이브러리만 쓰는 헤더(`SelfTestSession.h`)에 두고 네이티브 단위 시험을 붙인다. 계약 테스트는 쓰기 함수들이 맨 앞에서 이 판단을 부르는지 확인한다.
- Chromium e2e의 자체 시험은 게임과 조건을 맞춘다.
  - 배포되는 빌드(`vite preview`)로 돈다.
  - `sendDataToSKSE`를 미리 정의해 `hasLiveStats`가 게임처럼 false로 시작하게 한다.
  - `onSettingsChanged`를 덮어쓸 수 없는 속성으로 정의한다.
  - 14개를 페이지 하나에서 새로고침 없이 돌린다.
- 게임 시험 전후로 확인한다.
  - SKSE/Plugins 폴더(모드 폴더, Overwrite)의 파일 목록과 md5
  - 로그에 저장·내보내기 줄이 없는지
- 시험 뒤에 해 본다: 설정 바꾸기, 내보내기, 세이브 다시 불러오기, 메인 메뉴 왕복. 모두 파일을 바꾸지 않아야 한다.

## 완료 조건과 검증
1. 표시 파일이 없으면 지금과 똑같이 동작한다.
   - 검증: 계약 테스트(`scripts/*.test.mjs`)로 다음을 확인한다.
     - 시험 세션이 아닐 때 설정 전송·저장·수치 전송 경로가 바뀌지 않음
     - 표시 파일 확인이 한 곳에만 있음
   - 기존 vitest·e2e 통과
2. 시험 세션에서는 설정 파일이 바뀌지 않는다.
   - 검증
     - 계약 테스트: 저장 리스너가 시험 세션에서 `SaveSettingsAsync`를 부르지 않음
     - 게임 시험 전후 설정 파일의 md5 비교
3. 실행기가 시나리오를 모두 돌리고 결과 JSON을 만든다. Chromium에서는 모두 통과한다.
   - 검증
     - vitest: 플러그인 호출 가로채기와 해제(`nativeCalls.test.ts`), 설정 창 저장소 복원(`settingsPanelState.test.ts`)
     - e2e: 결과 형식과 자체 시험 통과(`selfTest.e2e.ts`)
4. 플러그인이 결과를 파일과 로그에 쓴다.
   - 결과가 크기 제한(1MB)을 넘으면 요약만 담은 짧은 보고를 쓴다. 파일 이름은 고정이다.
   - 검증: 네이티브 단위 시험(`*.native.test.mjs` 방식), Windows 검증 스크립트(DLL 빌드)
5. 게임에서 표시 파일을 두고 세이브를 불러오면 시험이 돌고, 결과 파일이 생긴다.
   - 검증: Claude가 결과 파일을 읽는다(사용자가 게임 실행).
   - 실패한 시나리오가 있으면 원인을 Ultralight 차이인지, 실행기 문제인지 나눠 보고한다.
6. README와 이 문서에 켜는 방법, 결과 위치, 안전장치를 적는다.

## 검수 반영 (2026-11-27)
- 다시 요청한 실행: 플러그인은 "시작했다" 보고를 못 받으면 다시 요청하고, 화면은 마지막으로 보낸 보고로 답한다.
  - 문제: 이 답은 보통 "running"인데, 플러그인은 "started"만 시작으로 쳐서 세 번 뒤 "시작 안 함"으로 결과를 덮어쓸 수 있었다.
  - 반영: 이제 "started"와 "running" 둘 다 시작으로 친다(`RunTrigger::NoteReport`, 네이티브 단위 시험 추가).
- 되돌리기 시나리오(`grow-up/undo-after-switch`, e2e 같은 이름)
  - 방향을 바꾸면 되돌리기 기록이 새로 시작하므로(grow-up 설계 문서), 전환 직후의 Ctrl+Z는 아무것도 하지 않는 것이 맞다.
  - 문제: 키가 페이지에 아예 닿지 않아도 통과했다.
  - 반영: 먼저 목록을 한 칸 옮기고 Ctrl+Z가 실제로 되돌리는지 확인한다(대조군). 그다음 전환 뒤 Ctrl+Z가 아무것도 되돌리지 않는지 본다.
  - 기록 초기화를 빼면 e2e가 실패하는 것을 확인했다.
