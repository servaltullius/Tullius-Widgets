# 자동 숨김과 자유 카메라 표시 설계 (2026-11-24)

## 배경
- 툴챈 로모씨(2026-11-02): "이제 토글만 있으면 좋겠군아. 이머시브 허드에 적응했더니 UI 없는 화면에 익숙해짐." 11-13: 이머시브 허드는 SkyUI·SkyHUD·moreHUD·TrueHUD·STB만 같이 숨기고 Tullius는 남는다.
- 툴챈 돌아온엣헴이(2026-10-23, 1.9.0 글 댓글): SexLab 자유 카메라에서도 체력·지구력·매지카 위젯을 보고 싶다.
- 조사(Codex, 2026-11-24): 해당 iHUD는 Fuzzles의 ImmersiveHUD SKSE(3.2.2). 다른 모드의 Scaleform 메뉴 투명도를 직접 바꾸는 방식이라 Prisma UI 웹 화면인 Tullius에는 닿지 않는다. 현재 상태를 읽을 공개 API는 없다. 기본 페이드는 나타남 약 0.17초, 사라짐 약 0.33초. SexLab·OStim 모두 엔진 자유 카메라(`PlayerCamera::IsInFreeCameraMode()`)를 쓴다.
- 사용자 결정(2026-11-24): 이번에는 Tullius 자체 자동 숨김과 자유 카메라 옵션만 만든다. iHUD 투명도 따라가기는 나중에 따로.

## 현재 동작 (바꾸기 전)
- 전역 `general.combatOnly`(전투 중에만), `general.showOnChangeOnly`(값 변화 시에만, `changeDisplaySeconds` 1~15초). 둘 다 켜면 AND. `resolveHudVisibility`(view/src/utils/hudPresentation.ts:262)에서 판정.
- 위젯별 `showWhen`(always/combat/change/combatOrChange)은 그대로 둔다.
- 숨길 때 `HudWidgetItems`가 `null`을 반환해 즉시 사라진다(페이드 없음).
- 자유 카메라: 네이티브 `IsBlockingUiState`(src/WidgetVisibilityState.cpp)가 `IsFreeCameraModeActive()`면 Prisma 뷰 전체를 숨긴다.
- 페이로드에는 `inCombat`과 체력·매지카·지구력 비율이 있고, 무기 꺼냄·웅크림·자유 카메라는 없다. 평소 500ms, 전투 중 100ms 간격으로 갱신.

## 사용자 관점
설정 → 일반 → "표시 방식"(지금의 "전투 중에만"·"값 변화 시에만" 자리)을 다음으로 바꾼다.
- **자동 숨김** 켜기/끄기(기본 끔). 켜면 평소에는 HUD 전체가 서서히 사라지고, 아래 조건 중 하나라도 맞으면 나타난다.
  - 전투 중 (기본 켬)
  - 무기·주문을 꺼냈을 때 (기본 켬)
  - 웅크렸을 때 (기본 끔)
  - 체력·매지카·지구력 중 하나라도 가득 차지 않았을 때 (기본 켬)
  - 값이 바뀌었을 때 (기본 켬, 기존 "표시 유지 시간" 1~15초 사용)
- **숨김 지연**: 조건이 모두 끝난 뒤 사라지기까지 0~30초(기본 3초).
- **페이드**: 나타남 0.2초, 사라짐 0.5초로 고정(iHUD 기본과 비슷). 설정 항목은 만들지 않는다.
- **자유 카메라에서**: 숨김(기본, 지금과 같음) / 체력·매지카·지구력만 / 전체. 숨김이 아니면 자유 카메라 동안에는 자동 숨김을 무시하고 보인다(장면 중 확인 목적).
- 설정 창이 열려 있으면(편집 모드) 항상 보인다(지금과 같음). F11 숨김 단축키는 지금처럼 HUD 전체를 숨긴다(자동 숨김보다 우선).
- 위젯별 표시 조건은 자동 숨김과 별개로 계속 적용된다(자동 숨김은 HUD 전체, 위젯 조건은 개별).

## 동작 방식
### 네이티브
- 페이로드에 `weaponDrawn`(`player->AsActorState()->IsWeaponDrawn()`), `sneaking`(`player->IsSneaking()`), `freeCamera`(`IsFreeCameraModeActive`와 같은 판정)를 추가. StatsJsonWriter와 view 타입·정규화에 반영.
- 반응 속도: 지금은 하트비트가 500ms마다 무조건 전송하므로 무기를 꺼내도 최대 0.5초 늦다(iHUD 나타남 0.17초). 하트비트 스레드의 100ms 폴링마다 게임 태스크로 `weaponDrawn`·`sneaking`·`freeCamera`를 읽어 직전 값과 다르면 즉시 전송을 요청한다. 전체 통계 수집은 늘리지 않는다.
- 화면의 "값이 바뀜" 시그니처(`buildItemChangeSignatures`)에는 이 세 값을 넣지 않는다(무기를 집어넣는 것만으로 다시 나타나지 않게).
- 자유 카메라 차단: 설정 JSON의 `general.freeCameraDisplay`를 읽는다. `JsonUtils`에 문자열 멤버 읽기(`TryReadStringMember`)를 추가하고, 기존 `TryReadUIntMember`와 같은 실제 멤버 경로·마지막 중복 규칙을 따르며 이스케이프가 없는 짧은 ASCII 값만 받는다. 테스트는 공용 실행기의 `json_utils_test.cpp`에 추가하고 기존 uint 사례는 건드리지 않는다.
  - 값이 `hide`이거나 없거나 알 수 없으면 지금처럼 차단, `vitals`/`all`이면 **자유 카메라 판정만** 차단 사유에서 뺀다. 읽는 시점은 단축키와 같다(시작 시 저장된 설정, 설정 저장 때마다).
  - `IsBlockingUiState`의 다른 사유는 그대로 둔다: 메뉴 시스템 숨김(`tm`), 게임 일시정지(`tfc 1`로 시간을 멈춘 경우 포함 여부는 게임에서 확인), 모달·애플리케이션 메뉴, 알려진 숨김 메뉴(콘솔 포함), 이름에 photo·screenshot·capture·freecamera가 든 일시 메뉴. 즉 자유 카메라 옵션은 "카메라 상태 때문에 숨기던 것"만 푼다.

### 화면
- 설정: `general.autoHide = { enabled, showInCombat, showWeaponDrawn, showSneaking, showResourcesNotFull, showOnChange, hideDelaySeconds }`, `general.freeCameraDisplay: 'hide' | 'vitals' | 'all'`.
- 마이그레이션은 스키마 버전이 아니라 **들어온 `general.autoHide`가 없을 때**만 한다(프리셋 파일에는 `schemaVersion`이 없어서 버전 기준이면 새 프리셋도 다시 마이그레이션된다). 스키마 버전은 7 그대로.
  - `autoHide`가 없고 `combatOnly`나 `showOnChangeOnly`가 켜져 있으면 `autoHide.enabled = true`, `showInCombat = combatOnly`, `showOnChange = showOnChangeOnly`, 나머지 조건 끔, `hideDelaySeconds = 0`(예전처럼 바로 숨김).
  - 예전에 둘 다 켰을 때의 AND(전투 중이면서 값이 바뀔 때)는 OR로 바뀐다. 드문 조합이라 받아들이고 릴리스 노트에 적는다.
  - `combatOnly`·`showOnChangeOnly`는 파일에 그대로 남긴다(구버전 view와 호환). 새 view의 판정·UI는 `autoHide`만 쓴다. `autoHide`가 있으면 레거시 값은 무시한다.
- 판정(`resolveHudVisibility` 확장):
  - 하드 숨김(그리기 안 함): 실시간 통계 없음, F11 등으로 `visible` 꺼짐.
  - 자유 카메라: `freeCamera && freeCameraDisplay !== 'hide'`면 자동 숨김 무시하고 표시. `vitals`면 `player.health/magicka/stamina`만 보이게(위젯 레이아웃의 `visible`은 존중: 사용자가 끈 위젯은 그대로 숨김).
  - 자동 숨김: 조건 중 하나라도 참이면 표시 목표, 모두 거짓이 된 시각부터 `hideDelaySeconds` 뒤 숨김 목표.
- 판정 결과는 두 가지로 나눈다: `render`(하드 숨김이면 false → 지금처럼 `HudWidgetItems`가 그리지 않음)와 `opacityVisible`(자동 숨김 목표).
- 페이드: HUD 래퍼(`tw-hud-font-root`)에 `opacity`와 `transition`(나타남 0.2초, 사라짐 0.5초)만 준다. `transform`·`filter`는 쓰지 않는다(안의 `position: fixed` 위젯 기준이 바뀌므로). 자동 숨김으로 숨을 때는 언마운트하지 않는다(페이드 아웃이 보이도록, 변화 감지 상태 보존).
- 자원 "가득 참": `healthPct/magickaPct/staminaPct >= 99.5`를 가득 참으로 본다(반올림 흔들림 방지).
- 조건 판정에 쓰는 시간은 기존 `nowMs` 갱신(변화 창 타이머)과 같은 방식으로, 숨김 예정 시각에 맞춰 한 번 깨운다(250ms 폴링 추가 금지).

## Codex 교차 검토 반영 (2026-11-24, gpt-6.2-astra) — 위 본문보다 이 절이 우선
원문: 세션 scratchpad `autohide-review.md.codex-20261124-054928.md`(23건). 핵심은 원본 코드로 확인했다.

### 표시 우선순위 (화면, 위에서부터 먼저 결정)
1. 실시간 통계 없음 → 그리지 않음.
2. 설정 창 열림(편집 모드) → 모든 활성 위젯을 그리고 불투명(지금처럼 F11·자동 숨김·자유 카메라 무시).
3. 유효 `visible`이 꺼짐(F11 세션 숨김 또는 저장된 "위젯 표시" 끔) → 그리지 않음.
4. 자유 카메라(`stats.freeCamera`):
   - `hide` → 그리지 않음(화면도 직접 숨긴다. 네이티브 차단과 별개로 설정 변경 직후의 시간차를 막음).
   - `vitals` → `player.health/magicka/stamina` 중 **레이아웃에서 켠 것만**, 그 위젯들의 `showWhen`은 무시하고 그린다. 셋 다 꺼져 있으면 설정 옵션 아래에 "자원 위젯이 모두 꺼져 있어 아무것도 보이지 않습니다" 안내. 다른 위젯은 그리지 않는다. 마스크는 저장값을 바꾸지 않는다.
   - `all` → 평소 위젯별 규칙대로 그림. 자동 숨김은 적용하지 않음(불투명).
5. 자동 숨김(켜진 경우) → 그리되 래퍼 opacity 0/1로 페이드. 꺼져 있으면 불투명.
- 온보딩, 경고 배너, 편집 가이드, 설정 창은 자동 숨김·자유 카메라 마스크와 무관(지금의 F11과 같음).
- 위젯별 `showWhen`은 지금처럼 즉시 적용된다(전투 전용 위젯은 전투가 끝나면 바로 빠짐). 자동 숨김의 "언마운트하지 않음"은 *자동 숨김 때문에는* 언마운트하지 않는다는 뜻이다. 효과 목록의 기존 예외(효과가 있으면 표시)는 유지.
- 완전히 숨은 동안에도 위젯을 마운트해 둔다(자식 타이머 비용은 작음). 변화 감지는 App에 있으므로 영향 없음.

### 시간 판정
- 자동 숨김 조건(전투·무기·웅크림·자원 부족·값 변화)을 매 평가에서 실제 `Date.now()`로 계산한다(오래된 `nowMs`를 쓰지 않음).
- "값 변화"는 **켜진 위젯의 값 변화**만 뜻한다: `lastChangeAtByItem`(위젯별 시그니처)의 최신 시각이 `changeDisplaySeconds` 안이면 참. 전역 시그니처의 전투 비트는 쓰지 않는다(전투는 별도 조건).
- 조건이 하나라도 참인 동안 `lastActiveAt = now`. 모두 거짓이면 `now - lastActiveAt < hideDelaySeconds*1000`인 동안 보이고, 지나면 숨김 목표. 조건이 다시 참이 되면 즉시 표시(지연 취소).
- 첫 통계부터 모두 거짓이면 처음부터 숨김(지연 없음). 설정 창을 닫은 순간, F11로 다시 켠 순간, 자유 카메라가 끝난 순간에는 `lastActiveAt = now`로 두어 지연만큼 보였다가 숨는다.
- 깨움: 값 변화 만료와 숨김 만료 중 가장 이른 절대 시각에 타이머 하나만 예약하고, 깨어나면 현재 시각으로 다시 판정한다. 250ms 폴링은 추가하지 않고, 레거시 `showOnChangeOnly` 폴링 effect는 제거한다.

### 네이티브
- **100ms 상태 폴링은 하지 않는다**(현재 전송 경로에서 "즉시 전송"과 "전체 수집 증가 없음"이 양립하지 않고, 태스크 적체·스레드 문제가 있음). 1차안: 기존 전체 페이로드에 `weaponDrawn`·`sneaking`·`freeCamera`를 추가하고 기존 500ms 주기와 이벤트를 유지한다. 게임에서 무기 꺼냄→표시 지연을 재 보고 필요하면 후속으로 다룬다.
- 기존 복구 경쟁 수정: 메뉴 이벤트가 `HideView()`로 숨긴 뒤 하트비트가 차단을 관측하지 못하면 다시 보이지 않을 수 있었다(기존 결함). `HideViewIfReady`(main.cpp, 모든 숨김 경로의 종착점)가 숨길 때마다 런타임의 `menusWereHidden`을 세우게 해, 다음 가시성 점검에서 차단이 없으면 복구되게 한다.
- `freeCameraDisplay` 읽기: `JsonUtils`의 기존 멤버 경로 스캐너가 찾은 최종 토큰을 기존 JSON 문자열 디코더로 해석해 `hide/vitals/all`만 받는다(이스케이프 포함 유효 JSON은 view와 같은 결론). 그 외·부재·잘못된 타입은 `hide`. 상위 `general`이 마지막에 비객체로 교체되면 부재.
- 설정 적용: 단축키와 같은 지점(시작 시, 설정 저장 때)에서 읽고, 값이 바뀌면 가시성을 다시 평가한다(다음 점검을 기다리지 않고 한 번 점검 요청).
- 혼용(새 DLL+구 view, 구 DLL+새 view)은 지원하지 않는다. 같은 버전 쌍으로 배포한다. 새 view는 구 페이로드에서 세 필드가 없으면 `false`로 본다.

### 설정·호환
- 마이그레이션 판정은 병합 전 **원본 `saved.general`에 `autoHide` 키가 없을 때**만. 키가 있으면 필드별로 검증해 잘못된 값만 기본값으로(부분 객체·잘못된 타입·범위 밖 지연은 0~30으로 자름).
- 이관하면서 `combatOnly`·`showOnChangeOnly`를 **false로 바꿔 둔다**(구버전 view로 되돌렸을 때 옛 플래그가 남아 다르게 동작하지 않도록. 구버전에서는 HUD가 항상 보이는 안전한 기본이 된다). 새 view의 판정·UI는 레거시 필드를 쓰지 않는다.
- 저장은 지연 이관: 다음 정상 저장 때 기록된다. 그 전에는 매 로드마다 같은 결과로 다시 이관된다(멱등).
- `hideDelaySeconds=0`이어도 0.5초 페이드가 있어 예전의 즉시 숨김과 다르다. 두 레거시 토글을 함께 쓰던 AND는 OR가 된다. 둘 다 릴리스 노트에 적는다.
- "표시 유지 시간"(`changeDisplaySeconds`) 슬라이더는 위젯별 "값이 바뀔 때"에도 쓰이므로 항상 보이게 옮긴다.
- 자원 "가득 참"은 `>= 99.5`(최대값 0이면 네이티브가 100을 보냄).
