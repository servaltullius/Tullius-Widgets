# 화면 브라우저 자동 테스트 (2026-11-26)

지금까지 화면 동작은 jsdom 단위 테스트와, 제가 그때그때 손으로 돌린 Playwright 확인으로 검증했다. 손으로 돌린 확인은 위젯 위치, 드래그, 실제 레이아웃 같은 것이다. 이를 고정 테스트로 만들어 바꿀 때마다 자동으로 돌게 한다. 그러면 게임 확인은 엔진(Ultralight)에서만 드러나는 항목으로 줄어든다.

## 사용자 결정 (2026-11-26)
- `@playwright/test` 1.65.1을 개발 의존성으로 추가하고, 테스트용 Chromium(headless shell)을 내려받는다.
- GitHub Actions의 `Frontend Lint & Test` 작업에서도 돌린다. 이 작업이 필수 검사(`test`)라서, 실패하면 PR이 병합되지 않는다.

## 설계
- 테스트 파일은 `view/e2e/*.e2e.ts`이다. vitest가 집어 가지 않도록 이름을 `.e2e.ts`로 하고, Playwright 설정에서만 찾는다.
- Vite 개발 서버를 전용 포트(5299)로 띄운다. 화면 크기는 기본 배치 기준인 1920×1080이다.
- 플러그인 연결은 화면의 브리지 함수로 대신한다. 설정은 `updateSettings`, 상태는 `updateStats`, 설정 창 열기는 `toggleSettings`로 넣고, 저장은 `onSettingsChanged`를 가로채 확인한다.
- `npm run e2e`로 돌린다. Windows 검증 스크립트(`verify-runtime-windows.ps1`)에는 넣지 않는다. Windows에도 Chromium을 따로 받아야 하고, WSL과 CI가 같은 테스트를 이미 돌리기 때문이다.

## 완료 조건과 검증
1. `npm run e2e`가 WSL에서 통과한다. vitest(`npm test`)와 tsc/eslint는 e2e 파일을 포함해도 그대로 통과한다.
2. 시나리오
   - **지속 효과 위로 쌓기**
     - 방향을 바꿔도 목록이 제자리에 있다.
     - 해로운 효과가 맨 아래에 온다(컴팩트 세로·가로, 클래식 세로).
     - 효과가 줄어도 아래쪽 끝이 고정된다.
     - 오른쪽 모서리 배치에서 방향을 바꿔도 다른 위젯이 옮겨지지 않는다. 나중에 켠 위젯도 묶음 자리에 놓인다.
     - 방향을 바꾼 뒤 Ctrl+Z를 눌러도 목록이 옮겨지지 않는다.
     - 빠른 편집 카드가 "Y 위치(아래 끝)"으로 표시한다.
     - 드래그하면 실제 위쪽 끝으로 맞춤이 되고, 아래쪽 끝 좌표로 저장된다.
     - 크기 조절 핸들이 커서를 따라가고, 왼쪽 아래 모서리가 고정된다.
     - 기본 자리에서 효과 12개를 걸어도 레벨 위젯과 겹치지 않는다(표준·도로롱).
   - **지난 날짜:** 값이 표시되고, 세 배치에서 누적 플레이 시간과 겹치지 않는다.
   - **설정 파일 보호:** 깨진 설정을 받으면 위쪽 알림과 설정 창 안내가 뜬다. 설정 창만 열어서는 저장하지 않는다.
   - **드롭다운 키보드:** ↓로 열고 Enter로 고른다.
   - 검증: 각 시나리오가 수정 전 동작이면 실패하는지, 대표 항목 하나 이상으로 확인한다.
3. CI의 `test` 작업에 Chromium 설치와 `npm run e2e` 단계가 들어가고, PR에서 통과한다.
4. README와 이 문서에 실행 방법을 적는다.

## 결과 (2026-11-26)
- `view/e2e/`에 시나리오 14개를 만들었다.
  - 위로 쌓기 9개(쌓는 순서는 두 배치, 기본 자리는 표준·도로롱 각각)
  - 지난 날짜 3배치
  - 설정 파일 보호 1개
  - 드롭다운 키보드 1개
- 공통 도우미는 `e2e/hud.ts`에 있다. 설정·상태를 넣고, 저장을 가로채고, 위치를 잰다.
- 각 시나리오가 수정 전 동작에서 실패하는지 확인했다. 해당 수정을 잠시 되돌려 돌려 봤다.
  - Ctrl+Z 기록 초기화
  - 위로 쌓기 기본 자리
  - 아래쪽 끝 기준 드래그 변환
  - 읽기 실패 중 자동 저장 막기
  - 드래그 시나리오는 처음에 되돌려도 통과했다. 저장값과 그려진 위치만 비교했기 때문이다. "끈 만큼만 움직였는지"를 확인하도록 고쳤지만, 새 맥락 검수에서 맞춤 변환을 빼도 통과한다는 지적을 받았다. 그래서 목록 위쪽 끝을 레벨 위젯 위쪽 끝 3px 아래에 놓아, 정확히 맞춰지는지 확인하도록 다시 고쳤다.
  - 새 맥락 검수 뒤 추가한 시나리오도 각 수정을 잠시 되돌려 실패하는 것을 확인했다.
    - 맞춤 변환
    - 크기 조절 기준점
    - 쌓는 순서 CSS
    - 방향 전환 때 위젯 자리 저장: 되돌리면 나중에 켠 위젯이 80px 어긋났다.
- WSL에서 `npm run e2e` 14개가 통과했다. `npm test`, eslint, tsc, Windows 검증 스크립트도 그대로 통과한다.
- CI(`Frontend Lint & Test`)에 Chromium 설치와 `npm run e2e` 단계를 넣었다. 실패하면 trace를 아티팩트로 올린다. 작업 시간 상한은 10분에서 15분으로 늘렸다.
