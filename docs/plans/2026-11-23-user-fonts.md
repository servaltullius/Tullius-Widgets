# 사용자 폰트 설계 (2026-11-23)

## 배경
- 요청: Nexus wall416(2026-02-14, 03-19 "Different font support needed too"), 툴챈 로모씨(2026-11-02 폰트 커스텀 애드온 배포, "Prisma UI 폰트 바꾸기 개빡세네").
- 로모씨 애드온은 배포된 view 파일을 고쳐 프리셋 4개를 `MyFont-Regular/Bold`(TTF)로 바꿔치기했다. 업데이트마다 깨지는 방식이다.
- 현재 글꼴은 프리셋 4개(`default/readable/compact/classic`)뿐이고, 컴팩트 HUD 기본은 동봉 Pretendard(정적 굵기별 WOFF2+WOFF).

## 목표
아이콘 팩처럼 폴더에 폰트 파일을 넣으면 설정에서 고를 수 있게 한다. view 파일을 고칠 필요가 없게 한다.

## 사용자 관점
```
Data/PrismaUI/views/TulliusWidgets/user-fonts/<글꼴 이름>/<폰트 파일들>
예) user-fonts/메이플스토리/Maplestory Light.ttf, Maplestory Bold.ttf
```
- 설정 → 일반 → 글꼴 목록에 기존 프리셋 아래 "사용자 글꼴: <폴더 이름>"으로 나타난다.
- 고르면 **HUD(클래식 카드·컴팩트 HUD 모두)** 글자에 적용된다. **설정 창은 기존 프리셋 글꼴을 유지**한다. 장식 글꼴을 골라도 되돌리는 메뉴가 읽히도록 하기 위해서다.
- 폰트에 없는 글자(예: 영문 전용 폰트의 한글)는 기존 글꼴로 보인다.
- 폴더를 지우면 저장된 선택은 지우지 않고 프리셋 글꼴로 보인다. 폴더를 다시 넣으면 돌아온다.
- 새 글꼴은 게임을 다시 시작하거나 세이브를 불러오면 목록에 나타난다(아이콘 팩과 같음).

## 지원 파일
- 확장자: `.ttf`, `.otf`, `.woff2`, `.woff` (대소문자 무시). 문서에는 **게임에서 확인한 형식만** 권장으로 적는다(현재 근거: 동봉 WOFF2 동작, 커뮤니티 애드온 TTF 동작, WOFF 실패 보고 1건).
- 굵기는 파일 이름의 마지막 단어로 추정한다(대소문자·구분자 `-`, `_`, 공백 무시):
  Thin/Hairline 100, ExtraLight/UltraLight 200, Light 300, Regular/Normal/Book/Roman 400, Medium 500, SemiBold/DemiBold 600, Bold 700, ExtraBold/UltraBold 800, Black/Heavy 900. 그 외는 400.
- 이름에 `Italic`/`Oblique`가 들어간 파일은 쓰지 않는다.
- 같은 굵기로 추정되는 파일이 여럿이면 정렬 순서상 첫 파일을 쓴다.

## 동작 방식
### 네이티브 (`src/UserFonts.cpp/.h`, 아이콘 팩과 같은 구조)
- `Data/PrismaUI/views/TulliusWidgets/user-fonts` 아래 폴더를 훑는다. 최대 글꼴 32개, 글꼴당 파일 16개.
- 폴더 이름: 아이콘 팩 ID와 같은 규칙(`IsSafePackId`: UTF-8 글자, 숫자, 공백, `_ - . ( ) ' [ ]`, `.`으로 시작·`..` 포함 금지, 192바이트 이하). 규칙 밖이면 로그를 남기고 건너뛴다.
- 파일 이름: 같은 문자 규칙 + 지원 확장자. 규칙 밖이면 로그를 남기고 건너뛴다.
- 결과 JSON: `{"fonts":[{"id":"<폴더>","files":["Maplestory Bold.ttf", ...]}]}` (파일 이름 정렬).
- 새 브리지 호출 `updateUserFonts`. `SendSettingsToView`에서 아이콘 팩과 함께 **설정보다 먼저** 보낸다.
- 공통 규칙(`IsSafePackId`, UTF-8 변환)은 아이콘 팩과 공유하도록 작은 헤더로 뺀다.

### 화면 (view)
- `data/userFonts.ts`: JSON 재검증(같은 ID·파일 규칙, 개수 제한, 대소문자 무시 중복 제거), 굵기 추정, `@font-face` CSS 생성.
- `hooks/useUserFonts.ts`: `updateUserFonts` 브리지 수신, 컨텍스트 제공(아이콘 팩과 같은 방식).
- 설정: `general.userFont: string`(빈 문자열 = 사용 안 함). 스키마 검증은 `iconPack`과 같은 방식. 기존 `fontPreset`은 그대로 두고 설정 창 글꼴과 폴백에 쓴다.
- 글꼴 선택 목록: 기존 프리셋 + `user-font:<id>` 항목. 사용자 글꼴을 고르면 `userFont`만 바뀌고, 프리셋을 고르면 `userFont`를 비운다.
- CSS 적용:
  - 선택된 글꼴에 대해서만 `<style id="tw-user-font">`에 `@font-face`를 만든다. family 이름은 `"TW User Font <id>"`(CSS 문자열 이스케이프).
  - 엔진이 굵기별 정적 face를 요구했던 기록이 있으므로, **100~900 각 굵기마다 face를 하나씩** 만들고 가장 가까운 파일을 연결한다(파일 하나면 모든 굵기에 같은 파일). view가 쓰는 굵기는 400/500/550/600/650/700.
  - `src`는 `url('user-fonts/<encodeURIComponent(id)>/<encodeURIComponent(file)>') format('truetype'|'opentype'|'woff2'|'woff')`, `font-display: block`.
  - `--tw-font-hud`, `--tw-font-compact` 앞에 사용자 family를 붙이고 기존 스택은 폴백으로 둔다. `--tw-font-ui`(설정 창)는 그대로.
- 실시간 전환 시 글자 잘림 방지: 동봉 폰트 주석대로, 글꼴 교체 전에 배치된 글자가 옛 폭을 유지해 잘린 적이 있다. 글꼴을 바꾼 뒤 `document.fonts`가 있으면 `load()`/`ready`를 기다리고, 없으면 타이머(예: 300ms, 1500ms)로 HUD를 다시 그리게 한다(HUD 루트 key 갱신 등).

- README 기능 목록에 한 줄.

## Codex 교차 검토 반영 (2026-11-23, gpt-6.2-astra) — 위 본문보다 이 절이 우선
원문: 세션 scratchpad `userfonts-review.md.codex-20261123-223801.md`. 지적은 원본 코드로 사실 확인했다.

1. **CSS 문자열 (수용)** `'`는 허용 문자이고 `encodeURIComponent`가 바꾸지 않아 `url('…')`가 깨진다.
   - URL은 경로 조각마다 `encodeURIComponent` 후 `'`→`%27`, `(`→`%28`, `)`→`%29`도 인코딩하고, CSS에는 큰따옴표 문자열로 넣으며 `"`·`\`·개행은 CSS 이스케이프한다.
   - family 이름은 사용자 ID를 쓰지 않고 내부 ASCII 이름 `TW User Font <n>`(선택이 바뀔 때마다 증가하는 번호)로 만든다. `<style>`에는 `textContent`로만 넣는다.
2. **이름 규칙 일치 (수용)** 폰트 폴더·파일 이름 규칙을 **바이트 기준으로 정의**해 C++와 TS가 똑같이 판정하게 한다.
   - 허용: 0x80 이상 바이트(비ASCII 전부), ASCII 글자·숫자, 공백, `_ - . ( ) ' [ ]`. 금지: `.`으로 시작, `..` 포함, 앞뒤 공백, 끝의 `.`. UTF-8 길이 192바이트 이하(TS는 `TextEncoder`로 잰다), 비어 있으면 안 됨.
   - 파일 이름은 확장자 포함으로 같은 규칙을 적용한다. 아이콘 팩 규칙은 이번에 바꾸지 않는다(범위 밖).
   - 공통 C++ 헬퍼(UTF-8 변환·바이트 규칙)는 새 헤더로 두되 아이콘 팩 동작은 그대로 둔다.
3. **형식 (수용)** 확장자 네 개를 찾되, 문서에는 게임에서 확인된 형식만 "권장"으로 적고 나머지는 "인식은 함"으로 적는다.
4. **face 구성 (수용)** 9개 face 대신 **실제 파일이 있는 굵기마다 face 하나**. 같은 굵기의 다른 형식 파일은 같은 face의 복수 `src`(woff2 → woff → otf → ttf 순)로 둔다. 파일 하나뿐이면 400 face 하나(엔진 합성 굵게 여부는 게임에서 확인). 결과를 보고 필요하면 매핑을 추가한다.
5. **재배치 (수용)** 기존 `markFontsReadyWhenLoaded`는 시작 때 한 번, 컴팩트(`html.tw-fonts-ready .tw-compact`)에만 작용한다.
   - 사용자 글꼴 적용·해제마다 HUD 루트(클래식·컴팩트 공통 조상)에 텍스트 속성을 실제로 바꾸는 클래스를 번갈아 달아(예: `tw-font-pass-a`/`tw-font-pass-b`가 `font-kerning: normal`/`auto`처럼 서로 다른 값) 재배치를 강제한다.
6. **로딩 경쟁 (수용)** 선택마다 세대 번호를 두고 최신 선택의 완료만 적용한다. `document.fonts.load()`로 사용 굵기(400/500/600/700)와 `'가Aa1'`을 요청하고, 결과가 비거나 실패·시간 초과(예: 5초)면 사용자 family를 빼고 프리셋 스택으로 표시한다(저장값은 유지). API가 없으면 타이머 뒤에 재배치만 한다. 전환·언마운트 때 타이머와 이전 `<style>`을 정리한다. 같은 목록을 다시 받아도 선택이 같으면 다시 로드하지 않는다.
7. **remount 금지 (수용)** HUD 루트 `key`를 바꾸지 않는다. 드래그 중 상태·변화량 표시를 보존한다.
8. **드롭다운 (수용)** `CustomSelect` 메뉴에 최대 높이(뷰포트 안)와 세로 스크롤, 긴 이름 말줄임을 넣는다(아이콘 팩 목록에도 이득). 글꼴 최대 32개.
9. **두 필드 저장 (수용)** 프리셋을 고를 때 `userFont`가 비어 있지 않으면 `fontPreset`을 `persist:false`로 먼저, `userFont: ''`를 마지막(저장)으로 보낸다. 비어 있으면 `fontPreset`만 보낸다. 사용자 글꼴을 고르면 `userFont`만 보낸다.
10. **저장값과 발견값 (수용)** 조회는 대소문자 무시(`findUserFont`), URL·옵션에는 발견된 실제 철자를 쓴다. 저장값이 목록에 없으면 선택기는 프리셋을 보여 주고 "저장된 글꼴 '<이름>'을 찾지 못해 기본 글꼴로 표시 중" 안내를 띄운다. 저장값은 지우지 않는다.
11. **스키마 (수용)** 스키마 버전 7 유지. `userFont`는 누락·잘못된 타입·규칙 위반이면 `''`, 유효한 문자열은 그대로. 프리셋 export/import는 `general`을 통째로 다루므로 자동 포함(파일은 별도 설치 안내).
12. **`TryReadUIntField` 오인 (보완, 범위 밖)** 기존부터 있는 단순 검색 파서 문제(아이콘 팩 ID도 같음). 이번 기능에서는 고치지 않고 별도 작업으로 남긴다.
13. **클래식 레벨 숫자 (수용)** `.tw-experience-level-mark span`의 Georgia에도 사용자 family를 앞에 붙인다(`--tw-font-level` 변수, 기본은 기존 Georgia 스택).
14. **폭 부족과 재배치 결함 구분 (수용)** 게임 확인에서 "저장 후 시작한 화면"과 "실시간 전환 화면"을 같은 위치에서 비교한다. 의도된 말줄임은 유지.
15. **굵기 판정·한도 순서 (수용)** 확장자 하나를 뗀 이름을 소문자로 만들고 글자만 남긴 뒤, 긴 키워드부터(`extrabold`, `ultrabold`, `semibold`, `demibold`, `extralight`, `ultralight`, `hairline`, `regular`, `medium`, `normal`, `light`, `black`, `heavy`, `thin`, `bold`, `book`, `roman`) 포함 여부로 판정한다. `italic`·`oblique` 포함 파일 제외. 모든 후보를 모은 뒤 정렬·중복 처리하고 그다음 한도(글꼴 32, 파일 16)를 적용한다. 한도로 빠진 항목은 로그.
16. **링크 (반대에 가까운 보완)** 목록에 있는 파일만 URL로 만든다. 심볼릭 링크·정션은 일반 파일·폴더로 보이는 대로 둔다(MO2 가상 Data와 충돌하지 않게). 별도 루트 비교는 하지 않는다.
17. **실패 격리 (수용)** 항목별 예외를 잡아 그 항목만 제외하고 로그. 0바이트 파일 제외. 크기 상한은 두지 않는다(CJK 폰트는 수십 MB일 수 있음). 파일 내용은 읽지 않는다.
18. **전송 순서 (보완)** 아이콘 팩과 같은 경로(설정 전 전송, 빈 목록도 전송)를 쓴다. 이 경로는 아이콘 팩으로 게임에서 동작 확인됐다. 목록→설정, 설정→목록 어느 순서로 와도 같은 결과가 되게 화면은 둘을 독립적으로 보관하고 렌더 시 결합한다.
19. **MO2·애드온 안내 (수용)** 문서에 압축 루트 예시, 두 애드온이 같은 폴더 이름을 쓸 때 합쳐지는 문제, 한·영 경고를 넣는다.
20. **번역·라이선스 (수용)** 새 문구는 한·영 내장 키로 추가. 문서에 "재배포 허용 폰트만, 라이선스 파일 동봉" 안내.

- 파일 판정 순서: 확장자·이탤릭 확인 → 이름 규칙(위반이면 경고) → 0바이트 제외. 영문 대소문자만 다른 파일은 정렬 뒤 하나로 합치고 그다음 16개 한도를 적용(네이티브·화면 동일).
- 굵기 판정(15항 갱신): Book·Roman·Normal·Regular는 마지막에 본다(`Bookman-Bold` → 700).
- 단일 파일(4항 갱신): 400으로 고정하지 않고 추정 굵기 그대로 등록한다. Bold 파일 하나를 400으로 등록하면 굵은 글씨에 합성 굵게가 겹치기 때문이다. 엔진의 가장 가까운 굵기 선택이 다른 굵기 글자를 그 파일로 그린다.
- 로딩(6항 갱신): 굵기마다 따로 끝나며, 하나라도 읽히면 사용한다. 동기 예외도 그 굵기만 실패로 친다. 제한 시간은 10초 + 파일당 5초이고, 시간이 다 되면 그때까지 읽힌 굵기가 있으면 사용한다. `Promise.allSettled`는 쓰지 않는다(빌드 대상 ES2019).
- 재배치(5항 보강): 동봉 Pretendard가 사용자 글꼴보다 늦게 준비되면 `tw-font-pass-*`가 시작 규칙을 가리므로, `fontsReady`가 `tw-fonts-ready` 이벤트를 보내고 App이 그때 다시 재배치한다.
- 안내: 불러오는 중 상태를 설정 창에 표시, 긴 이름은 줄바꿈. 같은 이름 파일 교체 후에는 재시작이 필요하다고 문서에 적었다.
- 반영하지 않은 것: 비ASCII 대소문자 조회 차이(ς), 드롭다운 메뉴가 프리셋 글꼴을 상속하지 않는 기존 동작, 스캔 비용 상한, 보이지 않는 문자가 든 이름 — 영향이 작거나 기존 동작이라 범위 밖으로 둔다.
