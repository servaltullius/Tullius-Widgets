# 설정 창 + 배치 편집 모드 (2026-11-24)

`2026-11-24-panel-redesign.md`(서랍, 시안 A)를 대체한다. 디자인 토큰, 컨트롤(스위치·세그먼트·슬라이더·선택 메뉴), Esc 소유 알림(`escapeOwners`, 플러그인 `onEscapeOwner`), 패널 배율 `--ps`, 자동 붙기 규칙(`panelDock.ts`)은 그 문서의 결정을 그대로 쓴다. 서랍 구현은 `refs/backup/panel-drawer-a`에 백업돼 있다(커밋 아님).

## 배경과 결정
- 사용자 의견: 사람들이 시안 B(가운데 창, 왼쪽 분류 목록)를 원한다.
- 시안 B의 약점: 창이 화면 가운데를 덮어 배치 편집 중 위젯을 가린다(Gemini 비교 검토에서도 가장 큰 단점으로 꼽힘).
- 사용자 선택(2026-11-24): "설정 창"과 "배치 편집"을 두 모드로 나눈다. 설정은 시안 B 모양의 창에서, 배치는 창을 접고 얇은 편집 막대만 남긴 채 화면 전체에서 한다.

## 두 모드
| | 설정 모드(기본) | 배치 편집 모드 |
|---|---|---|
| 들어가는 법 | 설정 키(Insert)로 열면 항상 이 모드 | 창의 "배치 편집" 버튼 |
| 화면 | 설정 창(왼쪽 분류 목록 + 내용) | 화면 위(또는 아래) 가운데의 얇은 편집 막대 |
| 위젯 끌기·크기 | 된다(지금처럼). 끄는 동안 창은 흐려지고 클릭이 통과 | 된다. 화면 전체가 열려 있음 |
| 위젯 클릭 | 위젯 옆에 빠른 편집 카드 | 위젯 옆에 빠른 편집 카드 |
| 나가는 법 | Esc 또는 닫기 → 패널 닫힘 | Esc 또는 "설정으로" → 설정 모드, "닫기" → 패널 닫힘 |

- 모드는 저장하지 않는다. 패널을 닫았다 열면 설정 모드.

## 설정 창
- 크기(1080p 기준): 폭 `min(940px×ps, 94vw)`, 높이 `min(720px×ps, 92vh)`. 왼쪽 목록 폭 210px×ps.
- 위치: 화면 세로 가운데. 가로는 자동 붙기 규칙으로 HUD가 적은 쪽 가장자리에서 32px×ps 안쪽(왼쪽/오른쪽). "설정 창 위치: 자동/왼쪽/오른쪽" 설정은 그대로 유지(단축키와 언어 분류). 헤더의 "반대쪽에 붙이기" 버튼은 없앤다(창은 배치 편집 모드로 비켜 줄 수 있으므로).
- 왼쪽 목록: 위에 "툴리우스 위젯", 묶음 제목 아래 분류 8개, 맨 아래에 "배치 편집" 주 버튼.
  - 설정: 표시와 모양(`display`), 단축키와 언어(`hotkeys`)
  - 위젯: 성장·플레이어(`progression`), 저항·방어·공격(`combat`), 장비·이동(`equipment`), 효과·시간(`effects`)
  - 배치: 위치와 크기(`layout`), 슬롯과 프리셋(`slots`)
- 오른쪽 내용: 분류 제목 + 한 줄 설명, 오른쪽 위에 "닫기 Esc". 내용만 세로 스크롤.
- 분류 안의 기존 섹션(experience, playerInfo, resistances, defense, offense, equipped, movement, time, timedEffects, presets, layoutTools)은 접히지 않는 묶음 제목으로 둔다. 아코디언·"모두 펼치기/접기"·펼침 상태 저장은 없앤다(옛 저장 키는 읽지 않음). `data-section-id`는 유지.
- 섹션 → 분류: experience·playerInfo → progression, resistances·defense·offense → combat, equipped·movement → equipment, time·timedEffects → effects, layoutTools → layout, presets + 배치 슬롯 → slots.
- 마지막으로 본 분류는 기존 `activeTab` 저장 키에 저장(값이 새 id가 아니면 `display`).
- 드래그 중 흐림: 위젯을 끌거나 크기를 바꾸는 동안(`interactionMode`가 있을 때) 창은 불투명도 0.12, `pointer-events: none`. 끝나면 돌아온다.

## 배치 편집 모드
- 설정 창 대신 편집 막대(높이 약 48px×ps, 폭은 내용만큼)를 화면 위 가운데에 띄운다. 들어갈 때 위젯 사각형과 화면 위쪽 띠(막대 높이 + 여백)의 겹침이 아래쪽 띠보다 크면 아래에 띄운다. 모드 안에서는 위치를 바꾸지 않는다.
- 막대 내용: "배치 편집" · 안내 "위젯을 끌어 옮기고, 모서리를 끌어 크기를 바꿉니다. Ctrl+Z 되돌리기" · [설정으로 Esc](주 버튼) · [닫기].
- 숨긴 위젯을 편집 중에 보여 주는 기존 동작, 정렬 안내선, 화살표 키 이동, Ctrl+Z/Y는 그대로.

## 빠른 편집 카드 (두 모드 공통)
- 설정 창 안 맨 위에 있던 카드를 위젯 옆 떠 있는 카드로 옮긴다. 내용·`data-*` 속성은 그대로(표시, 잠금, 크기, X/Y 위치, 표시 조건, 위치 초기화, 앞/뒤).
- 카드에 "관련 설정" 버튼을 더한다: 위젯의 `groupId`가 속한 분류로 이동(배치 편집 모드면 설정 모드로 돌아가서).
- 위치: 위젯 사각형 오른쪽(간격 12px×ps)에 위쪽 맞춤 → 안 들어가면 왼쪽 → 그래도 안 되면 아래 → 위. 화면 안으로 잘라 맞춘다. 카드 폭 300px×ps.
- 위젯이 움직이면(드래그 끝, 화살표 이동, 크기 변경, 초기화) 위치를 다시 잰다. 드래그·크기 변경 중에는 카드를 숨긴다.
- 설정 모드에서 카드가 창과 겹치면 카드가 위(카드 z > 창 z).

## Esc 순서
단축키 캡처 > 열린 선택 메뉴 > 위젯 선택 해제 > 배치 편집 모드 → 설정 모드 > 패널 닫기.
- 페이지: 배치 편집 모드의 Esc 처리기는 선택 메뉴가 열려 있거나 위젯이 선택돼 있으면 양보한다(`escapeOwners`에 종류별 조회 추가). 처리하면 이벤트를 소비한다(패널 닫기 처리기는 `defaultPrevented`를 무시).
- 플러그인: 배치 편집 모드 동안 페이지가 Esc를 소유한다고 알린다(`claimEscape('layoutMode')`). 플러그인 쪽 코드 변경 없음.

## Codex 설계 검토 반영 (2026-11-24, packet 모드) — 위 본문보다 우선
원문: 세션 scratchpad `review-settings-window.txt.codex-20261124-140222.md`.

수용
- 닫기 처리기 문구 정정: 패널 닫기 처리기(`useSettings`)는 `defaultPrevented`인 Esc를 **건너뛴다**(닫기·unfocus 모두).
- Esc 처리기는 등록 순서와 무관해야 한다. 배치 편집 모드 처리기는 소비 전에 단축키 캡처·열린 메뉴·선택(`hasEscapeOwner('selection')`)을 모두 확인하고, 처리하면 `preventDefault`+전파 중단. 선택 메뉴의 Esc 처리기도 단축키 캡처 중이면 양보한다.
- 키 반복: 페이지의 Esc 처리기(메뉴·선택·모드·패널 닫기)는 `event.repeat`이면 무시한다(한 번 누름에 한 단계).
- 모드 소유 알림은 `useLayoutEffect`로 걸어 버튼 클릭 직후 첫 Esc보다 먼저 플러그인에 닿게 한다. 그래도 클릭 직후 수 ms 안의 Esc는 이론상 닫기로 갈 수 있다(미확인, 실사용에서 드묾).
- `escapeOwners`는 플러그인 콜백이 없거나 실패하면 보고 상태를 갱신하지 않아, 다음 변화 때 다시 보낸다.
- 모드 수명: 패널이 열릴 때마다 설정 모드로 초기화. 배치 편집 모드는 `settingsOpen`을 그대로 둔 채 표시만 바꾼다(편집·되돌리기 기록·선택 유지). 설정에서 옮긴 뒤 배치 모드에서 Ctrl+Z가 이어지는지 확인.
- 드래그 상태 전달: App이 `interactionMode`를 패널에 넘긴다. 선택만 한 위젯은 카드가 보이고, 끄는 중일 때만 창 흐림·카드 숨김.
- 버튼 동작: [배치 편집]·[설정으로]는 선택을 유지한 채 즉시 전환. [관련 설정]은 분류를 바꾸고 설정 모드로 돌아가며 선택을 해제하고 해당 `data-section-id`로 스크롤. 전환 뒤 초점은 새 표면의 주 버튼으로.
- 설정 모드에서 창 뒤에 있는 위젯은 잡을 수 없다(창이 먼저 클릭을 받음). 그 경우는 배치 편집 모드를 쓴다. 안내 문구에 반영.
- 자동 위치: 클래식은 실제 두 후보 창 사각형(왼쪽/오른쪽, 세로 가운데)과 위젯 사각형의 2차원 겹침 면적으로 비교한다(띠 비교 폐기). 동률·미측정은 오른쪽. 컴팩트는 앵커 규칙 유지.
- 창 크기: 폭 `min(940×ps, 화면폭 − 2×여백)`, 높이 `min(720×ps, 화면높이 − 2×여백)`. 왼쪽 목록은 자체 스크롤, [배치 편집] 버튼은 목록 아래 고정.
- 편집 막대 위·아래 판단은 막대 폭(가운데) 띠만 비교(구현됨). 막대 폭은 실제 렌더 크기를 쓰지 않고 상한(760×ps, 화면폭)을 쓴다 — 진입 전에는 막대가 없어서.
- 카드: 선택 ID의 DOM ref로 실제 사각형을 렌더 뒤(`useLayoutEffect`) 측정. 매 렌더 재측정하되 바뀔 때만 상태 갱신. 카드 최대 높이 = 화면높이 − 2×여백, 넘치면 카드 안 스크롤. DOM이 없으면(측정 실패) 화면 오른쪽 위 여백 자리에 둔다.
- 포털: 창·막대·카드가 공유하는 레이어 안의 단일 포털 자리. 레이어는 `pointer-events: none`, 표면(창·막대·카드·메뉴)만 `auto`. 위치는 JS로 계산한 정수 px(`transform` 안 씀).
- 화살표 이동은 선택 메뉴가 열려 있으면 양보한다.
- 위젯 레지스트리의 모든 `legacyGroupId`가 분류로 연결되는지 테스트.

보완(미확인으로 남김)
- 플러그인 Esc 예약과 페이지 소유 알림의 실제 순서, 클릭 통과·포털 좌표·클리핑의 Ultralight 동작은 게임에서만 확인 가능.
- 드래그 도중 Esc(선택 해제) 뒤 늦은 마우스 놓기: 기존 동작 그대로이며 이번 변경 범위 밖.

반대
- 옛 탭 값 `combat`/`effects`가 새 분류 id와 같은 문자열이라 다른 분류로 열리는 문제: 세션 저장값이라 게임을 다시 켜면 사라지고, 결과도 유효한 분류라 무해.
- 버튼의 "Esc" 표시가 선택 해제 단계와 다를 수 있다는 지적: 버튼 자신의 단축키 표시로 충분.

## 다른 모드 영상에서 가져온 것 (2026-11-24, 사용자 결정) — 위 본문보다 우선
참고: 사용자가 보여 준 다른 모드(TJDR)의 HUD 편집기 영상과 제작자 코멘트("상세 설정 창이 HUD를 놓고 싶은 자리를 가려 출시 직전에 막대·창 위치 조절을 넣었다").
- 가림: 위젯을 끄는 동안 편집 막대도 설정 창처럼 흐려지고(불투명도 0.12) 클릭이 통과한다. 막대에 "아래로/위로" 버튼을 두어 직접 옮긴다(들어갈 때의 자동 위치는 그대로).
- 배치 편집의 Esc = 취소: 들어갈 때의 `itemLayouts`를 기억해 두고 취소하면 통째로 되돌린다. 바뀐 게 없으면 아무것도 쓰지 않는다. 되돌리기 직전에 되돌리기 기록의 묶음을 끊어(`useLayoutHistory().checkpoint`) Ctrl+Z로 취소 자체를 되돌릴 수 있다. "적용"은 그대로 두고 설정 창으로 돌아간다. 막대의 "설정으로"·"닫기" 버튼은 "취소 Esc"·"적용"으로 바뀐다. Insert로 패널을 닫으면 편집 내용은 남는다. Esc 순서는 메뉴 > 선택 해제 > 배치 편집 취소 > 패널 닫기.
- 휠: 설정이 열려 있을 때 위젯 위에서 휠로 크기(0.05씩, 위젯별 최소·최대 안, 잠긴 위젯 제외, 그 위젯을 선택), Shift+휠로 공통 배경 진하기(`general.opacity`, 5씩, 10~100). 위젯별 투명도 설정은 없어 공통 값을 쓴다. Shift+휠이 가로 스크롤로 오는 엔진을 위해 deltaX도 읽는다.
- 처음 쓰는 사람 안내: "위치와 크기" 분류의 편집 안내에 그림 3단계(끌어서 옮기기 / 휠로 다듬기 / 적용 또는 취소)를 인라인 SVG로 둔다.

## 인게임 확인 1차 (2026-11-24)

- 배치 편집 모드에서 Esc를 눌러도 반응이 없었다(패널도 닫히지 않음). 나머지는 사용자 확인으로 문제없음.
- 확인된 사실: 패널이 닫히지 않았으므로 플러그인은 Esc를 받았고 페이지 소유 알림도 닿았다. 페이지 쪽 처리만 일어나지 않았다.
- 가설(미확정): 게임 안에서 Ultralight 뷰가 Esc keydown을 받지 못하거나, `key`가 `'Escape'`가 아닌 값으로 온다. 둘을 가르는 증거는 아직 없다.
- 조치: 원인과 관계없이 동작하도록 페이지가 Esc를 가진 동안 플러그인이 받은 Esc를 `handleEscape()`로 페이지에 넘긴다. 페이지는 Esc 처리를 `utils/escapeOwners.ts` 한곳에 모아(단축키 입력 대기 > 선택 메뉴 > 위젯·묶음 선택 > 배치 편집 순) 한 번 누름에 한 단계만 처리하고, keydown과 플러그인 전달이 같은 누름으로 겹치면(300ms 안) 먼저 온 쪽만 처리한다. Esc 판별은 `key`·`code`·`keyCode`를 모두 본다.
- 같은 이유로 메뉴 닫기, 선택 해제, 단축키 입력 취소의 Esc도 게임에서는 동작하지 않았을 수 있다. 다음 인게임 확인에서 네 상태(메뉴 열림, 위젯 선택, 배치 편집, 단축키 입력 대기)를 모두 본다.

## 검수(/code-review) 반영 (2026-11-24)
