# 지속 효과 목록 위로 쌓기 (2026-11-26)

툴리우스 채널 요청이다. 지속 효과 목록을 화면 아래쪽에 두면 효과가 늘어날 때 아래로 자라 화면 밖으로 밀린다. 그래서 아래쪽 끝을 기준점으로 두고 위로 쌓이게 하는 옵션을 넣는다.

## 사용자 결정 (2026-11-26)
- **정렬:** 위로 쌓을 때는 중요한 효과(해로운 효과, 곧 끝나는 효과)가 기준점인 맨 아래에 온다. `+N`은 맨 위에 붙는다.
- **위치:** 방향을 바꾸는 순간 목록은 화면에서 움직이지 않는다. 그 뒤로 늘어나는 방향만 바뀐다.

## 설계
- 설정 `timedEffects.growDirection: 'down' | 'up'`, 기본은 `'down'`(지금 동작)이다.
- 위로 쌓을 때 목록 위젯의 저장 좌표 `y`는 **아래쪽 끝**을 뜻한다. 화면은 `translateY(-100%)`로 그리고, 확대·축소는 왼쪽 아래를 기준으로 한다.
  - 드래그는 화면이 정한 위쪽 좌표에 높이를 더해 저장한다.
  - 방향키 이동과 휠·키 크기 조절은 차이만 적용하므로 따로 바꿀 것이 없다. 마우스 크기 조절 핸들은 고정되는 왼쪽 아래 모서리에서 커서까지 거리로 배율을 잰다.
- 방향을 바꿀 때는 목록 높이만큼 `y`를 옮겨 화면 위치를 유지한다. 목록이 숨겨져 높이를 잴 수 없으면 빈 목록 한 줄 높이로 환산한다.
  - 다른 위젯 중 아직 저장되지 않은 것(기본으로 꺼진 위젯 등)은 지금 자리를 함께 저장한다. 오른쪽 모서리 배치는 위로 쌓을 때의 목록 자리까지 넣어 묶음 위치를 정하므로, 저장하지 않으면 방향을 바꿀 때 나머지가 80px(도로롱 96px) 옮겨진다.
- 기본 위치(배치 초기화, 새 설치)
  - 컴팩트: 자원 막대 바로 위(1080 기준 y=975)에서 위로 쌓인다. x는 레벨 위젯 오른쪽(표준 656, 도로롱 756)이다. 아래로 쌓을 때의 기본 칸에는 위쪽에 레벨 위젯이 있어서, 그 옆으로 옮겨 위쪽이 화면 끝까지 비게 했다. 오른쪽 모서리 배치는 이 위치까지 포함해 묶음을 옮긴다.
  - 클래식: 원래 위쪽 끝 자리 아래 y=400을 아래쪽 끝으로 쓴다.
- 컴팩트에서 보여 줄 줄 수의 상한은, 위로 쌓을 때 화면 위쪽 끝까지로 계산한다.
- 배치 슬롯에는 방향도 함께 저장한다. 불러올 때 방향도 되돌린다(예전 슬롯은 아래로).

## 완료 조건과 검증
1. 설정 창의 지속 효과 항목에 "쌓는 방향(아래로/위로)"이 있고, 바꾸면 목록이 제자리에 있다.
   - 검증: vitest(설정 병합, 방향 전환 시 y 변환), 브라우저 확인
2. 위로 쌓을 때 목록의 아래쪽 끝이 고정되고, 효과가 늘면 위로 자란다. 중요한 효과는 맨 아래에 온다.
   - 대상: 컴팩트(세로·가로)와 클래식(세로·가로)
   - 검증: vitest(렌더 순서·속성), 브라우저 확인
3. 위로 쌓을 때 드래그, 방향키 이동, 크기 조절, 맞춤 가이드가 제대로 동작한다. 저장된 위치는 아래쪽 끝 기준이다.
   - 검증: vitest(드래그 좌표 변환), 브라우저 확인
4. 배치 초기화와 새 설치에서 방향에 맞는 기본 위치를 쓰고, 배치 슬롯이 방향을 함께 저장하고 되돌린다.
   - 검증: vitest
5. 게임에서 효과를 여러 개 걸어 위로 쌓이는지 확인한다(사용자).

## 결과
- 브라우저 확인(효과 3개)
  - 방향을 바꿔도 목록 위치가 그대로였다.
  - 위로 쌓으면 해로운 효과가 맨 아래에 왔다.
  - 효과가 줄어도 아래쪽 끝이 고정됐다.
  - 드래그하면 아래쪽 끝 좌표로 저장됐다.
- 2026-11-26 사용자 인게임 확인: 위로 쌓기, 방향 전환, 효과 증감, 배치 편집과 다시 켠 뒤 위치를 확인했다.

## 검수(/code-review) 반영 (2026-11-26)
- 방향을 바꾸면 배치 편집 되돌리기 기록을 새로 시작한다. 되돌리기는 위치만 되돌리므로, 방향이 바뀐 뒤 예전 위치가 다른 끝 기준으로 읽히는 것을 막는다.
- 위로 쌓을 때 컴팩트 기본 자리를 레벨 위젯 오른쪽으로 옮겼다. 효과 수를 늘려도 레벨 위젯을 덮지 않는다.
- 목록을 꺼 둔 채 방향을 바꾸면, 빈 목록 한 줄 높이(컴팩트 15, 클래식 34에 배율을 곱한 값)로 위치를 환산한다.
- 위로 쌓을 때 빠른 편집 카드는 "Y 위치(아래 끝)"으로 표시한다.
- 아래쪽 끝 기준 드래그 변환을 `snapWidgetMoveWithAnchor`로 분리하고 테스트를 붙였다.

## 새 맥락 검수 반영 (2026-11-26)
- 오른쪽 모서리 배치에서 방향을 바꾸면 저장되지 않은 위젯이 옮겨지던 문제를 고쳤다. 방향을 바꿀 때 아직 저장되지 않은 위젯의 지금 자리를 함께 저장한다(`pinItemLayoutsForGrowSwitch`).
  - 불러올 때는 보이는 위젯만 저장된다. 그래서 질병 저항처럼 기본으로 꺼진 위젯을 나중에 켜면 80px 왼쪽에 놓였다. 브라우저 테스트로 재현하고, 수정 뒤 통과를 확인했다.
- 위로 쌓을 때 마우스 크기 조절 핸들이 커서를 따라가지 않던 문제를 고쳤다. 배율을 왼쪽 위가 아니라 고정되는 왼쪽 아래 모서리 기준으로 잰다.
- 브라우저 테스트를 보강했다.
  - 드래그 시나리오는 실제 위쪽 끝으로 맞춤이 되는지 확인한다.
  - 크기 조절, 오른쪽 모서리 방향 전환, 클래식 세로·컴팩트 가로의 쌓는 순서를 추가했다.
- 남은 것
  - 클래식은 줄 수 상한이 없다. 아래로 쌓을 때도 원래 없었다. 기본 자리(아래쪽 끝 y=400)에서 표시 개수를 9개 이상으로 올리면 목록 위쪽이 화면 밖으로 나갈 수 있다. 클래식 줄 높이는 내용에 따라 달라서 상한을 따로 정해야 한다.
  - 위쪽 모서리 배치에서 위로 쌓으면, 효과가 11개를 넘을 때 목록이 화면 위쪽의 나침반 쪽까지 자랄 수 있다.
